# Write a trap fable

Start with what someone does twice even when the second choice costs them. Write one sentence naming the belief, the action, the consequence and the available alternative. Check the definition against a reliable source for a named effect. Treat the animal as fictional. Avoid diagnosing a person from one example.

1. Inspect the clips the user actually provides. Probe formats, group duplicate encodes by matching several visual moments, inspect the opening, a repetition, the pivot and the last frame. Keep time ranges approximate when sampled. With the bundled project, read `docs/reference-analysis.md`.
2. Build the story backwards from one ordinary decision in a recognisable place. Give the human the same two options as the animal. If the animal wants food but the human wants approval, show the common decision mechanism explicitly or change the analogy.
3. Draft five first lines with different visual contradictions. Read each one over the first drawing. Choose one that makes the viewer able to predict an action, leaves a real question, and can pay off on screen. Discard vague promises and claims about how many people fall for the trap.
4. Use the reference pacing as a starting point. Show the problem in the first three seconds. Repeat one physical action two or three times. Change the evidence or cost on each repetition. Let a bystander demonstrate the unused alternative. Give the main character a beat to notice it. Switch to a single human setting around two-thirds through. Resolve the opening object on the last line.
5. For Hindi/Hinglish, write as if telling a friend a story. A sentence like “तीन सौ रुपये तो जा चुके। अगला घंटा किसका है?” gives the narrator somewhere to pause. Keep Roman captions in a separate field. Expand spoken numbers. Speak the draft aloud or synthesize it before trimming.
6. Hand the director a clean script plus one visible action and one exact spoken anchor per beat. Include what must already be on screen, what changes and where the next shot starts. In the bundled project preserve the fields in `episode/story.json`, use one Roman token per spoken token, and pick a cue word present in that line. Rewrite repeated cue words if the intended occurrence would be ambiguous. Add visual IDs to the director for new shots.

Apply the review in [the beat review](references/beat-review.md). Deliver the selected hook, the reason for it, script, cue sheet and one sentence describing the payoff. Report actual retention only from supplied audience data.
